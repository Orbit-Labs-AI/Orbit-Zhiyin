## 范围与执行环境

- 本机 macOS、Apple Silicon；`os.cpu_count()` 返回 14。该数字不等于所有核心都能持续提供相同推理吞吐。
- 模型：本地 multilingual-e5-small ONNX，384 维，CPUExecutionProvider；没有远程推理，没有使用随机或哈希向量替代实际资源的语义向量。
- 文档前缀 `passage: `，查询前缀 `query: `；最多 512 token 的窗口，重叠 64 token，窗口内 masked mean、窗口间 mean、L2 归一化；持久化为 float16，评分时分块转换为 float32。
- 本次真实 E5 运行的模型标识：`e5:48cb79be690d33d30f830bfe84225b174686241c30cd99d06115e2d0b392d073`。标识包含模型与 tokenizer 文件摘要、池化与窗口参数、运行时版本等；不同标识不得混用向量。
- 各吞吐试验使用每进程 2 个 ONNX CPU 线程、模型内部 batch 8、每次传入最多 64 段。除单独列出的构造索引基准外，吞吐计时不包含数据库写入；预热和模型初始化也不计入推理秒数。

## 真实 E5 编码吞吐

### 新主源的真实 overview

在实际 SkillMD 来源导入过程中，以只读连接从当时已发布的资源中按 `item_id` 取前 500 条 skill，使用系统实际重建的 `chunk_texts(...)[0]`。平均长度为 386.066 字符；500 条文本重建耗时 0.292 秒。

| 1 | 2 | 5.051 秒 | 98.99 条/秒 |
| 2 | 2 | 3.763 秒 | 132.86 条/秒 |
| 4 | 2 | 1.931 秒 | 258.92 条/秒 |

本组是 500 条实际 overview 文本，不是随机抽样，也不是对全库完成时间的测量。若后续文本长度和负载相似，13.8 万条 overview 的纯推理约为 9 分钟；加入模型加载、文本重建、数据库写入及分片不均衡后，应以运行进度修正估计。

### 既有库的真实正文片段

从既有库读取 128 条实际正文，每条截取前 1200 字符作为**吞吐试验输入**，重复四次形成 512 条输入。这里的截取只用于测量，与生产正文分块策略无关；这组数据不证明正文全覆盖。

| Worker 数 | 每进程线程数 | 最慢进程推理时间 | 合计吞吐 |
|---:|---:|---:|---:|

| 2 | 2 | 9.269 秒 | 55.24 段/秒 |

补充试验中，64 条构造的长短混合文本使用真实 E5，单进程 2 线程的模型 batch 8 / 16 / 32 分别约为 116.8 / 107.6 / 84.9 段每秒。因此保留内部 batch 8，未凭 batch 越大越快的假设提高默认值。CoreML provider 在本机可用，但本次没有验证它的编译、兼容性、精度或吞吐；生产路径仍使用 CPU。

## 已修复的规模问题

实现入口：[vectors.py](../../packages/catalog/src/orbit_catalog/vectors.py)、[index.py](../../packages/catalog/src/orbit_catalog/index.py)。

1. **按批重复全库排序。** 原实现每批查询所有缺失块并按类型排序；现在按资源块主键 `(item_id, ordinal)` 进行 keyset 扫描。查询计划确认使用主键范围搜索。完成后重跑只扫描并跳过已有缓存，不重新编码。
2. **文本重建与去重。** 一个批次内每条资源只取一次分块文本；按模型和文本哈希复用持久缓存。读到的文本重新校验哈希，避免错误分块文本写入缓存。
3. **矩阵加载的内存峰值。** 不再 `fetchall` 全库向量、拼接完整 bytes 后再复制筛选矩阵；每次读取 1024 行。矩阵达到 64 MiB 使用临时文件映射；评分以最多 16,384 行的块转换为 float32。
4. **过期 SQLite 统计造成二次复杂度。** 构造规模试验发现，矩阵 SQL 连接资源表时可选择逐块扫描资源表。现在仅连接块与向量缓存，利用已加载的活动资源位置表筛选所有者，移除该查询计划风险。
5. **每批重建整个目录快照。** 向量写入更新独立 `embedding_generation`，只使向量矩阵失效；资源、筛选和特征快照继续使用目录的 `generation`。
6. **每资源最多四块的召回假设。** 检索按资源所有者聚合块分数，允许资源有任意数量的可编码块。全文模式不能依赖固定的 `4 × topK` 块候选截断。
7. **WAL 旧读事务与新缓存混用。** 用固定的旧读连接、另一个发布事务和新的缓存读取顺序复现了两种问题：旧事务误用更新的目录索引，以及旧向量读取回退全局矩阵版本。现在仅复用与当前连接版本相同的索引；旧事务按自己的快照临时构建，不覆盖较新的目录或矩阵缓存。目录版本与嵌入版本分别遵循此规则。

现有精确评分在已测 30 万块边界表现可用，因此本次没有引入 ANN 依赖。数百万块的载入、内存映射磁盘空间和查询性能仍须根据实际成库结果判断。

## 并行、取消与恢复

`index_embeddings_parallel` 默认单 worker，最多使用 `min(4, cpu_count // threads)` 个进程。通过一次 SQLite `ntile` 查询取得资源键分位边界；每个进程独立加载模型并负责互不重叠的资源范围。推理不持有写锁，只有注册模型和提交向量批次时使用短写事务。

- 已完成批次在 SQLite 中提交。后续编码异常、进程退出或取消均不撤销这些批次；重跑根据缓存跳过已完成文本。
- 同一文本哈希可能分布在不同 worker。若它们同时发现缓存缺失，可以发生重复推理；数据库主键与 `INSERT OR IGNORE` 保证最终仅保留一个缓存条目。**`computed` 是已提交批次中的编码输出次数，不是全局唯一向量数，也不是已覆盖资源数。**
- `indexed` 记录本次处理的缺失块行数；`reused` 记录批次内重复文本减少的编码次数。它们都不能代替全局覆盖统计。
- 正常取消广播事件，worker 完成当前批次后退出；并行监督器在收到取消后设置 15 秒宽限。若原生推理或写入等待未返回，明确抛出 `embedding_cancel_timeout` 并停止子进程。此异常表示需要读取覆盖统计或重跑，不表示整个任务完成。
- 子进程报告异常时，主进程明确失败并清理其他进程。非零退出码，以及连续两次空轮询确认的“退出但未交付结果”，都不会无限等待；第二次确认用于避开队列结果恰好在超时之后到达的竞争。
- 写锁竞争最多等待 30 秒。独立 CLI 编码与另一个来源同步进程并行运行时，长时间同步可能导致 `CatalogBusy: catalog_writer_busy`。该失败可恢复，不能把它隐藏为成功或无限延长等待。UI 的单任务限制并不约束独立 CLI 进程。
- 资源同步可以在某个分片已经完成后增加新资源。主进程最后重新计算全局覆盖；此时应明确返回 `partial`，而不是把所有 worker 已退出当作完整覆盖。同步结束后重跑可补齐。

macOS 使用 multiprocessing `spawn`。从 Python 调用应使用带 `if __name__ == "__main__"` 保护的文件入口；正常 CLI 入口可直接使用。默认单进程的取消在批次之间检查，不具备另一个进程强制中断原生推理的能力。

## 覆盖统计与完成条件

| 字段 | 含义 |
|---|---|
| `active_items` | 当前活动资源数，包含不同类型资源 |
| `indexed_items` | 至少一个已选块已有向量的资源数 |
| `overview_items` | ordinal 0 已有向量的资源数 |
| `eligible_fully_indexed_items` | 所有 `embed=1` 块均已有向量的资源数 |
| `fully_indexed_items` | 当前分块投影的全部块均已有向量的资源数 |
| `body_chunks` / `indexed_body_chunks` | 全部正文块数 / 已编码正文块数 |
| `full_body_items` | 至少一个正文块且所有正文块已编码的资源数 |
| `all_chunks` / `eligible_chunks` / `indexed_chunks` | 全部块 / 选入编码的块 / 已编码块的所有权行数 |
| `pending_chunks` | 已选块数减去已编码块数 |
| `missing_overview_items` | 活动资源数减去 overview 已覆盖资源数 |

`scope="overview"` 的 `ready` 仅表示每条活动资源的 ordinal 0 已有向量。`scope="all"` 的 `ready` 表示全部**已选块**已编码；若目录仍采用抽样策略，不能据此声称全部正文完成。用户要求全部正文时，应启用全文策略，并同时核验 `eligible_chunks == all_chunks`、`indexed_chunks == all_chunks`，以及正文块计数相等。

这些计数对应当前分块投影，不是“每个原文字符都有独立语义表示”的证明。现有分块会去除空白、以标题组织正文，并对相同块去重。超长 token 输入触发窗口数量上限时明确失败，不静默截断或制造全覆盖统计。
