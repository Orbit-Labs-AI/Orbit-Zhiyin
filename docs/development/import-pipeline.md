# 导入流程与恢复

导入任务将已授权来源整理成可发布的 canonical 投影。来源发现、文件捕获、记录标准化、分析与 UI 更新有各自状态；“提交成功”只表示任务被受理。

## 阶段和计数

| 阶段 | 在做什么 | 应显示什么 |
| --- | --- | --- |
| discover / capture | 找到允许的输入并索引或捕获变化 | 来源、文件数、读取错误 |
| prepare / map | 识别原生身份并生成标准事件 | 记录/事件计数、当前阶段 |
| derive | 生成会话、轮次、工具和模型调用 | 派生阶段与进度 |
| validate_projection | 校验引用、Schema 与完整性 | 校验状态和具体问题 |
| published | 原子发布自洽结果 | 发布版本、完成时间、覆盖 |
| analysis | 基于发布结果计算页面产品 | 计算状态与上次可用快照 |

`reset_projection` 等内部准备阶段可出现在日志中。不同来源会出现不同子阶段，文件、记录、事件与会话不能排成一个不断递减的漏斗。大文件或事务期间可能只有阶段变化，不承诺总完成百分比或 ETA。

## 新鲜度与读取

导入中的新记录不等于已可分析。App 可以显示上一次发布数据，明确标注更新时间或计算中。没有历史结果时显示加载/空态；失败不能回退成真实数据样式的 Demo。

未解析记录和未知事件有自己的覆盖原因。`partial` 不等于整个任务失败，任务完成也不代表来源所有字段完整。UI、CLI 与报告应复用共享覆盖语义。

## 取消与重试

CLI 的 Ctrl+C 以 130 退出，未完成投影事务回滚，已提交的捕获输入保留。重试同一 `ingest` 会复用未变化输入并继续处理。需要重建时显式运行 `orbit --home <目录> rebuild`；索引模式仍可能依赖源文件存在。

同步间隔和来源变化策略由调度器处理，避免上一轮尚未完成就重复整源导入。暂停/恢复只改变采集行为，已发布数据继续保留。锁冲突、源文件变化和单条坏记录必须保留不同原因，不能无限重试所有错误。

## 排障路径

先确认所选 home、来源和采样边界，再看任务最近进度、错误码和发布版本。核对是否只是大文件处理、分析计算或后台维护；只有失败原因明确时才重试。需要定位性能时记录各阶段、CPU/IO 负载和数据规模。

`desktop.log` 记录宿主/helper 信息，服务日志与任务状态解释后台流程。公开报告前脱敏；不要上传数据库或整段个人会话。用户操作见[排障指南](../guides/troubleshooting.md)。
