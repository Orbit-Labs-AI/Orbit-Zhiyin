# v0.12：先把画像和瓶颈看清楚

> 文档状态：版本记录。正文保留原基线、日期与证据；其中的状态和数字不代表当前版本。现行入口见[文档导航](../../README.md)。


> 状态：历史版本记录；描述当时行为，当前入口见仓库 README。
此前完整链路已有画像与事件证据，但它们主要藏在分析 JSON 中，读者很快就看到推荐，难以判断中间推导是否成立。这一版把中间产物独立输出，并让 CLI 按“数据、画像、瓶颈、推荐”顺序展示。

`portrait.py` 聚合任务要求与协作记录，生成画像、瓶颈案卷和标准化示例；它不读取资源目录。`analysis_reports.py` 负责说明这些结果。每次 report 额外保存 `profile / bottlenecks / process` 的 JSON 和 Markdown。

画像包括任务场景、要求覆盖的会话与任务数、请求与修改类别、原始证据，以及消息和工具调用的过程统计。瓶颈案卷保留最初请求、回复、后续反馈和缺失材料。它们描述观察，不生成性格、效率或节省时间分数。

CLI 默认给整条链路摘要，`--view profile / bottlenecks / process / recommendations` 可分别展开；`evidence` 在终端回看引用，不需要启动服务。虚构 demo 不输入“说人话”或 skill 名称，仍能从要求和修改记录匹配资源。

验证新增了独立构造的会话计数、任务计数、协作比例、完整证据顺序、来源行号、空目录、空数据和 CLI 案例。252 项测试与 lint 通过；文字对照 8/8，链路开发案例 34/34，措辞回归 12/12。先验证代码再运行真实样本；本地历史此前已被查看，不能当独立测试集。规则和推荐条件没有按该样本分布拟合权重。

新增副产品已跑通；主观可读性与资源收益仍待实际读者核验。后续难点是复杂任务边界和未留存的文件正文，不应靠增加人格维度来掩盖证据缺口。推导与计数口径见 [画像说明](../../modules/analytics/profiling.md)。
