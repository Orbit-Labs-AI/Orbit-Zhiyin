# v0.3：推荐来源可以实际获取和复核

> 状态：历史版本记录；描述当时行为，当前入口见仓库 README。
这一版补上了“资源从哪里来”。后端已实际取得 10 个公开来源的仓库信息和文档，保留固定提交、许可证信息和文件哈希。此前目录主要靠手动核对，现在可以用 `orbit catalog-refresh` 重复验证。

资源覆盖 skills、项目规则、插件、MCP、hooks、代码基准和代理。推荐仍由画像与瓶颈共同决定。新增来源目前用于调研，不因为进了目录就获得推荐资格；例如，代码修复基准的高分不能证明中文解释好读。

本版通过 39 项检查，也重新跑过真实样本的分析、报告和虚构 demo。测试覆盖了固定版本读取、哈希不符、损坏缓存、网络失败与写入中断。真实样本仍是快照中的 36 个会话，本次验收反馈没有进入画像。

全流程现在能执行，评价还不够。现有 8 组文字对照只能识别空话、明显术语堆叠、遗漏事实和无依据的效果声明。它们不能证明画像正确，也不能代替读者理解。下一版会把不同用户、不同场景和不该推荐的情况加入评价，重点检查从原始记录到建议的判断是否成立。

代码入口：`resource_fetch.py` 负责获取和校验，`catalog.py` 负责离线目录与缓存，`recommend.py` 只负责匹配分析结果。外部文档中的脚本和指令不会被执行。刷新失败时保留上次可核对的版本，并在输出中标明失败状态。
