# 后端编排

`orbit_backend` 将数据读取、分析、资源匹配和用户操作组合为 CLI、报告 API 与 App gateway。新业务逻辑放在职责模块，入口层负责参数、授权、任务与错误转换。

## 三种入口

| 入口 | 实现 | 使用场景 |
| --- | --- | --- |
| `orbit` CLI | `cli/`、`application/` | 导入、分析、报告和离线评价 |
| `orbit serve` | `api/` | 报告与数据 HTTP 接口，开发期查看 `/docs` |
| `orbit-helper gateway` | `services/` | App 页面、后台 worker、快照、推荐、安装、AI 与 SSE |

入口共享模块，但路由和鉴权不能互相假定。对接时应检查运行入口对应的 OpenAPI 与路由实现。

## 从事实到输出

1. `data_access` 在一个一致快照里读取 `orbit_data` 的标准事件和派生表，带上范围、版本、统计成员与覆盖。
2. `analytics` 计算八族特征、统计、任务关系、信号与展示产品；`profiling` 保留画像和报告所需的证据推导。
3. `features` 和 `uiview` 将测量结果组合成检索输入及页面模型。UI 只呈现已定义的分母和状态。
4. `recommend` 用问题、偏好、环境与 Catalog 召回并排序；结果仍保留适用性、来源和未匹配原因。
5. `reporting` 输出报告，`exporting` 服务 App 导出；安装与 AI 使用独立的预览、授权和任务流程。

## 必须保持的边界

- 原生日志解析属于 data，后端不创建另一套不一致的 mapper。
- `None`、空集合、未知时间、累计用量和未知工具结果遵循[输入契约](../contracts/analysis-inputs.md)。
- 文本要求、持续偏好、客观验证与用户评价分别归属不同特征族；不把引用中的话当作当前用户要求。
- 生成、评价和人工评分不自动回写成用户历史证据。评价使用独立数据目录与标签。
- `legacy` 支持显式旧库读取；兼容导出文件不承载新业务逻辑。

## 调试路径

先重现入口与范围，再检查读取覆盖、模块结果和最终呈现。若事实不完整，先修解析或范围；若事实正确而页面含义错误，修计算与呈现合同。以[链路验收](../development/acceptance.md)核对全流程，不通过演示数据补齐真实数据空态。
