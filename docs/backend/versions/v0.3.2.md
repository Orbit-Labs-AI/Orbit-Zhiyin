# v0.3.2：归档、恢复和未知状态都不能破坏分析

本版处理了真实使用中的三个边界。会话从活动目录归档、再恢复后，数据库只认当前来源，旧导入记录不能让排除策略失效。来源文件已消失时，只清理本次明确导入的数据目录；其他目录的记录保留。

工具状态进一步按工具契约判断。业务工具返回的 `exit_code` 字段可能是它读取的数据，不等于执行失败；只有命令工具的结构化状态或执行器状态头能说明退出码。没有可靠状态时保持未知。

报告现在独立展示卡点，即使资源目录没有对应建议。虚构 demo 也只打开自己的数据库，不再先触碰用户指定的正常数据库。

56 项检查通过，覆盖归档恢复后排除、移除来源、业务字段反例、无匹配建议仍展示卡点，以及 demo 隔离。下一版继续做任务情境与读者要求，让同一个人在不同任务中的要求不会混成一句笼统偏好。
