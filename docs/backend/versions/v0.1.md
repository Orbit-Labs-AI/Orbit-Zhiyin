# v0.1：能跑完流程，还不能验收画像

第一版已完成从 Codex 日志到中文分析和 skill 建议的完整数据流。命令行和 HTTP 接口共用分析代码；真实记录只在本地保存，仓库带虚构样本供团队复现。

本机固定历史快照后，导入了 36 个用户会话、41,746 个统一事件；审批与其他非用户会话没有参与画像。本次评价反馈也没有混入历史数据。

## 为什么这样做

先用流式读取和 SQLite，把来源、项目、模型与证据保存清楚。没有可靠的满意度标签，先报告明确要求和纠正候选，不训练人格模型。中文输出先交代发现，再给少量证据和下一步；复杂指标放在 JSON 的 details 中。

## 跑通到哪里

12 项自动测试通过，覆盖消息镜像、模型归属、重复导入、未写完的日志、审批过滤、评价隔离、API 与并发计时。8 组人工构造的明显好坏案例符合预期。用已导入的真实记录生成了本地报告。

这些检查证明数据流能运行，也证明了一部分边界处理；不能证明结果已经“说人话”。人工回看实际报告发现：规则会把“让代码简洁”误当成“让回答简短”，也会把数学任务里的验证要求混进泛化协作要求。这样的推荐依据仍不可靠。

## 下一版先修什么

先识别要求作用于什么：代码、解释、文档还是执行流程；把任务内容与表达偏好分开。推荐目前只是把要求与资源标签相匹配，还没有充分结合瓶颈，不满足产品目标。下一版必须由画像与瓶颈共同提供理由，说明为什么这个资源能针对当前问题。证据摘录要保留完整语义，避免在路径或词语中间截断。

当前完成度：数据闭环已跑通；稳定画像、真实瓶颈诊断和 skill 收益尚未验证。人工验收待进行。
