# v0.4：让画像和推荐适用于具体任务

这一版解决“把不同要求混成一句偏好”的问题。代码注释要简洁、给学生的证明要直观、开发报告要说清进展，这些要求现在分别保存在任务情境里。推荐也使用发生问题的原有场景，不能因为选了一个筛选条件，就把代码任务改成文档任务。

从真实快照里，数学讲解涉及 16 个会话，其中 4 个明确提出易懂要求；有任务把读者指定为大一学生。这只能说明相应任务的要求，不能推断用户本人是什么背景。同一会话中“没看懂，再直观些”这样的短跟进，会接续前面的任务与读者信息；换主题或换会话就不沿用。

62 项检查通过，真实报告、数学场景筛选和虚构 demo 都已跑通。报告先展示少量发现和一个卡点，把全部统计与引用留在 JSON。新增测试确认代码注释的简洁要求不会成为数学任务的简洁要求，任务读者不会跨会话继承，场景不匹配时不推荐。

仍需改善的是评价覆盖。当前场景和读者来自明确表达及少量上下文规则，遇到模糊换题可能漏判。下一版会用独立的正例、反例和条件删减检查整条链路，并把“自动检查通过”和“读者读懂”分别记录。
