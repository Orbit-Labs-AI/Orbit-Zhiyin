# v0.5：评价整条链路，而不只评价一句话

本版加入 34 个构造对照场景，从 JSONL 获取、标准化、画像、瓶颈到推荐，走的是正式代码。旧版有 10 个场景判断不符合预期：例如把“介绍测试驱动开发”记成要求执行测试，把“不要简短”反过来当成简洁偏好，或对已解释的术语继续推荐编辑工具。

根据这些错误，规则现在先核对要求的对象、否定和任务背景。预期失败的测试不进入排错瓶颈；已经给出紧邻解释的术语不再计入未解释术语；长度要求仍不能覆盖数学证明所需的条件。语言判断也区分“用中文”和题目里的 English API。

修改后 34 个对照场景全部符合预设标签，原有 8 个文字对照也通过。75 项测试通过；真实快照的报告已重新生成。评价会分别报告误报、漏报、证据是否能回看，以及删掉画像、瓶颈或场景后是否停止推荐。

这组数据是规则开发集：我们用它发现问题并修改，因此不能称为独立的人类评价或泛化成绩。每个场景在临时数据库中运行，用完即删，期待标签不会传给分析模块，也不会写进用户历史。当前真实建议依然只是待验证的试用。

下一步用新的改写与边界场景检查是否过度适应这 34 个例子，并检查实际报告的主次、读者背景和中文表达。自动判断正确只是基础；“读者能说出主要发现、为什么给这个建议、下一步怎么验证”才是验收要回答的问题。
