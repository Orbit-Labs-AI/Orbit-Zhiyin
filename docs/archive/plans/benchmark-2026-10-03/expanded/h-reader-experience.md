## 真人环节

读者先看正文并复述，再看事实核对；版本映射在评审前隐藏。评分未填保持 null，无法判断与不喜欢分别记录。建议先用已有 6 个构造案例，再由各成员在本机选择已授权的少量真实案例；只共享聚合，不集中原始历史。

H05 的目标脚本预先固定，主持人不提示点击哪里，先记录成功 / 失败和求助，再收意见。同一读者重做同一任务有学习效应，不能算多个独立样本。满意度、采纳意愿和 A 的真实任务收益分开报告。

解释必须能让读者区分事实、推断和建议；“这个 Skill 预计能缓解瓶颈”不能被文案改写成“已提升 X%”。发现准确数字但误导因果的表达，也记为事实保真失败。

## 可复用命令

```sh
pnpm check:ui
uv run --locked tandem eval run --suite readability --no-store --json .local/benchmark/s8-readability-01.json
.venv/bin/tandem reader-pack
```

`reader-pack` 输出实际目录后，用该路径执行 `reader-results --pack ... --ratings ...`。先检查命令对自定义输出的支持，不能假设 `reader-pack` 接受未实现参数。空白表不能由执行 session 自填“真人已通过”。

UI 行为检查可以与部分纯只读研究并行；其截图 / 浏览器与 CPU 开销仍会影响 G 的正式计时。需测正式 App 时先核对交付物，缺 target / 打包物就写 not_implemented，不为完成评测临时扩产品范围。

## 交付与完成条件

交付步骤脚本、构造 E2E 结果、匿名读者评分 / 复述统计、理解错误清单和界面证据。截图只作辅助，不能替代断言。S8 不凭自己的判断标记人工验收，不调整推荐算法，产品问题由对应功能 Issue 跟进。
