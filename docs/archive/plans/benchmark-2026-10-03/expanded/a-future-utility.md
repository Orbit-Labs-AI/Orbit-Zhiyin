## 样本和执行

首轮建议 20 个独立真实任务、至少两类工作；样本不足时报告实际 n。先通过独立真人复核，确认目标、边界、完整验收和开始前 checkpoint。没有旧 checkpoint 时建立新的前瞻 cohort，不把重建猜测当原始状态。

基础 Agent 配置、已有 memory / rules、工具、依赖、权限和网络条件对三种方法保持一致；推荐内容是唯一计划内差异。Skill 正文从冻结目录取，安装或注入的实际字节留摘要。每格启动新执行环境，清除跨方法残留；任务验收由相同检查判定，不能用模型自评的“完成了”。

运行顺序按任务区组随机或平衡安排，避免所有 baseline 冷机、所有 ours 热机。限额、取消、超时和异常按共同协议记账。若平台无法测量四类 Token 或恢复任务环境，标记对应格子缺失，继续完成可验证部分。

## 原生个性化与模型对照

“不推荐”只去掉 Orbit 增量，不去掉用户已有能力。与内置个性化的严格增量对照放在 C07。A06 每个模型配置单独报告，不能把厂商名称相同的思考档位当作同等计算量，也不能用公开榜单分数替代用户任务实验。

公开模型 benchmark 如后续需要，只进入背景先验：固定来源、日期、版本、harness 与任务映射，保留缺失。当前不采购、下载或执行外部榜单。

## 交付与完成条件

- `executions.json`：每格实测记录和摘要；来源必须真实标为 paired / historical / constructed。
- `metrics.json`：A01–A07 分别报状态、预计 / 有效 / 缺失 n；A01–A05 从现有评分器读结果，不手算覆盖机器输出。
- `report.md`：主对照、分层表、失败案例、推荐成本；长期与模型研究未具备时列出具体前置条件。

优先执行 A01–A04。A07 不为抢进度缩短必要观察窗后宣称长期收益；本 session 不调整推荐算法、验收标准或公共评分器。
