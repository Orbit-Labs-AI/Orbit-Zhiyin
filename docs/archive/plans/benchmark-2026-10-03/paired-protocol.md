# 共同协议

> 本页是 2026-10-01 至 10-03 的历史方案，文中的“当前”、TODO、测试数量和命令只对当时成立。现行入口：[评测](<../../../../evals/README.md>)。

[返回总入口](<paired-proposal.md>) · [Session 分工](<paired-session-prompts.md>)

本轮用简单的配对任务表，不等待完整历史重放框架。只固定下面六件事。

## 1. 任务、干预与验收先定

每任务保存：ID、来源（真实 / 构造）、原始需求、起始文件快照、验收检查、适用的既有约束。B 的干预由测试前可见历史生成并保存正文与来源；不得读取测试答案、未来结果或 A 的失败记录后再调整。验收者不能只看 Agent 的“已完成”自述。

A/B 同模型、档位、工具、原有配置和环境；各自从同一快照启动新会话。AB / BA 顺序各占一半，避免一组一直吃冷启动。正式每格一次，不择优重试；API 中断等非任务错误保留为缺失，重跑保留原记录。

## 2. 四个数字怎么算

设预先固定任务数为 N（默认 12）。全任务完成率用全部 N；节省只在 A/B 都通过的配对子集 S 上计算，同时醒目标出 |S| 和两组完成率。

| 指标 | 计算方式 |
| --- | --- |
| 完成率 | 预算内通过全部必需验收的任务数 / N；B−A 用百分点 |
| 首次交付通过率 | 第一次提交产物就通过全部验收、尚未经纠错的任务数 / N |
| 完成度（辅助） | 每任务“通过验收项 / 预设验收项总数”，再按任务取平均；验收项不在运行后细拆 |
| 需要纠错的任务占比 | 至少收到一次有效纠错的任务数 / N；同时报总纠错回合 / N |
| 净 Token 节省率 | `[ΣS A执行Token − ΣS B执行Token − Orbit额外Token] / ΣS A执行Token` |
| 净用时节省率 | `[ΣS A任务秒数 − ΣS B任务秒数 − Orbit额外秒数] / ΣS A任务秒数` |

“Orbit 额外开销”包括一次性历史分析和额外推荐调用。为简洁保守，首次试验把该批全部额外开销扣在成功配对子集上，不假定以后复用几十次。执行 Token 已含规则 / Skill 文本，不重复扣；已含在任务计时中的推荐步骤也不再加一次。全批实际用量另外列出，包括失败；分母为零时为 null，负节省如实展示为增加。

若一次性准备成本很高，可在“后续任务相似”的假设下估算回本任务数：`ceil(一次性成本 / 成功配对的平均每任务运行节省)`；每任务节省须先扣经常性推荐成本。分母≤0 就写未观察到回本，不能用这一预测替代本轮净结果。

## 3. 纠错和时间不要混口径

一次有效纠错是：明确指出未遵守原有需求 / 约束并要求修正的一轮反馈；同条反馈多个问题仍算一轮。新需求、普通确认、补充资料不算。工具失败与 Agent 自修次数另列，不能叫“用户纠错”。

由同一评审者按同一检查清单，在 Agent 提交产物或请求确认时反馈，两组最多 2 轮；有条件时隐藏 A/B 身份。AI / 脚本模拟反馈只能称“规则触发返工”，不能宣称真实用户少纠错。未做真人反馈就留空该项；零纠错但任务失败也不能写成更懂用户。

任务时间从执行器收到任务到通过验收或停止，包含工具、模型与实际反馈等待；排队未开始的时间单列，反馈等待另记以解释差异。台上称“任务端到端用时”，不把机器等待减少说成节省了同等人工工时。若反馈等待严重不均衡，时间只作观察，暂不用作主收益。

## 4. 预算和失败都保留

每任务固定 10k 总 Token、300 秒，先触达哪个就停止；最多允许 2 轮收到纠错后的修订，仍未通过则失败。每任务额外推荐调用计入其预算，一次性分析单列。输入 / 缓存读 / 缓存写 / 输出按互斥口径求和，未知不填零。此处称“共同执行预算”，净收益另包含全部一次性开销，不宣称一次性准备免费。

预算耗尽、验收失败计为失败；未运行、取消、计量缺失单列。未完成全部格子时，只展示已观察计数与缺失数，不把“完成者中的通过率”冒充全体结果。若 B 完成率更低，即使成功子集省 Token，也不能只报“总体更好”。

## 5. 只交三份文件和日志

- `tasks.json`：任务、固定条件、验收定义、快照与干预摘要；准备后只读。
- `runs.csv`：`task_id, arm, status, passed, first_pass, checks_passed, checks_total, total_tokens, elapsed_s, feedback_wait_s, corrections, log_ref`；total_tokens 只记执行调用，额外推荐调用另附明细，合并预算与净收益时各计一次。
- `report.md`：四项结果、逐任务表、全批开销、失败 / 缺失、实测范围；`logs/` 保存执行与验收证据。

这是最小记录格式提案，不是已实现的 CLI。真实输入与日志保存在 Hackathon `.local/benchmark/hackathon-<run>/`，不提交 team-hub；共享报告仅放脱敏聚合。只用已授权材料和执行环境。

## 6. 复用代码，别先造框架

现有 `evals/benchmark/contracts.py`、`metrics.py` 可参考 Token / 配对口径，但 `local / prepare / score` 面向冻结历史研究，不会自动执行这 12 个新任务，现有执行契约也没有纠错与部分完成字段。先用上述表和受控执行完成测量；补小型记录 / 汇总脚本即可，不先改公共 schema。真的满足历史研究契约时再复用其评分器，不能伪造历史锚点或真人标签来兼容。
