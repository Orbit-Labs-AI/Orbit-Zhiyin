# 并行Session执行说明

> 历史来源：本页为2026-10-01 至 10-03 的历史方案，2026-10-07 从团队 Vault 迁入。原位置：`项目/Orbit/benchmark/并行Session执行说明.md`。正文与原有日期、结论保留，仅整理导航和空白；私人会话定位不公开。本文中的“当前”、TODO、测试数量和执行命令仅对原文基线成立，本次没有重新验证，也不自动形成任务或授权。现行入口：[源码文档](<../../../../evals/README.md>)。

[总入口](<paired-proposal.md>) · [共同协议](<paired-protocol.md>)

只开 3 个 session。按任务分工，一次运行测完四项指标。准备者先固定任务与干预，其他 session 就能执行；不用等全模块评测。

| Session | 做什么 | 独占产物 |
| --- | --- | --- |
| S0 准备与汇总 | 固定 12 个任务、A/B 条件、验收和干预；试跑记录链路；最后合并数据、做一页结果 | `tasks.json`、分析开销、`report.md`、汇总表 |
| S1 修错与实现 | 执行 4 个修错 + 4 个实现任务，每任务 A/B 各一次，共 16 次 | `s1/runs.csv`、`s1/logs/` |
| S2 约束与纠错 | 执行 4 个约束任务，每任务 A/B 各一次，共 8 次；使用约定的真人反馈流程 | `s2/runs.csv`、`s2/logs/` |

S1/S2 的任务量不同，因为约束组需要更多人工反馈。需要均摊时由 S0 在开始前调分片，不能结果出来后换任务。只有 2 个 session 时，S0 准备完兼做 S2；只有 1 个就沿相同步骤串行。

同一任务两组在同一机器上跑。多机可以各跑完整配对；同机默认一次只执行一个 Agent，其他 session 并行准备、验收与汇总。必须同机并发赶进度时，先交 Token / 完成 / 纠错结果，时间结果等固定子集独占复测后再展示，避免把资源竞争当收益。

沿用仓库已有环境和测试。纯执行可读同一固定 checkout，输出分目录；要改脚本则各用不冲突的工作树 / 文件，不同时改分支、公共配置和锁文件。发现业务 bug 记下来，不为让数字更好边跑边改算法。版本改了，相关对照重新成对运行并留旧结果。

## 直接复制给新 session

代码工作目录：`Action Mesh/Hackathon`。规划位于 `../team-hub/Hackathon/benchmark/`。这里是未来任务包，本次不自动启动 session。

### S0

```text
请执行 Orbit 黑客松 benchmark 的 S0。读 ../team-hub/Hackathon/benchmark/benchmark硬效果.md 与共同协议.md，并遵守仓库 AGENTS。
目标只是一套 12 任务 × A/B 两组的试验，测净 Token、净用时、完成率、纠错。准备 4 个修错、4 个实现、4 个约束任务，先保存起始文件、验收、既有规则与实际 Orbit 干预；别看测试答案再选建议。
用 2 个不入正式结果的构造例子验证记录，然后冻结 tasks.json、模型、预算和分片。确认已有数据 / 执行授权；缺项如实记录，不伪造真人复核或自动推荐。手工干预须另列来源。
不构建完整评测平台、不跑旧 60 项。复用现有执行方式，必要时只补最小记录 / 汇总脚本。按共同协议记录 Orbit 自身开销，收齐 S1/S2 的 CSV 与日志后，给出一页结果和逐任务表，失败 / 缺失保留。不得自动创建或联系其他聊天。
```

### S1

```text
请执行 Orbit 黑客松 benchmark 的 S1。读 ../team-hub/Hackathon/benchmark/benchmark硬效果.md、共同协议.md，并遵守仓库 AGENTS。
使用 S0 已固定的 tasks.json，只跑分给你的 4 个修错和 4 个实现任务，A/B 各一次。每组从同一快照启动，保留相同模型、原有 memory / rules、工具和验收；按冻结顺序交错运行。
同一轮记录 Token、用时、完成 / 首次通过、验收项和纠错，不按指标重复执行。已有真人反馈才记录用户纠错；工具重试单列。预算耗尽保留失败，计量缺失不补零，不择优重跑、不临时改 Orbit 建议。
只写 .local/benchmark/hackathon-<run>/s1/ 的 runs.csv 和 logs；只在已授权环境执行。时间测量避开同机竞争。交付计数、成本、失败与原始日志位置，正式评分由 S0 统一完成。
```

### S2

```text
请执行 Orbit 黑客松 benchmark 的 S2。读 ../team-hub/Hackathon/benchmark/benchmark硬效果.md、共同协议.md，并遵守仓库 AGENTS。
使用 S0 已固定的 tasks.json，只跑分给你的 4 个约束与协作任务，A/B 各一次；要求真实工作产物，不能用问答“记住偏好”代替任务。
两组保留相同任务要求与原有规则，用同一真人评审者、同一检查清单、相同反馈节点，最多 2 轮纠错。不要替真人填写评价；如果只有脚本反馈，称为规则触发返工，真实用户纠错指标留空。
同时记录 Token、用时、完成 / 首次通过、纠错回合和反馈等待，只写 .local/benchmark/hackathon-<run>/s2/ 的 runs.csv 与 logs。只在已授权环境执行，不改冻结建议、不择优重试。交付完整结果与缺失，交 S0 汇总。
```
