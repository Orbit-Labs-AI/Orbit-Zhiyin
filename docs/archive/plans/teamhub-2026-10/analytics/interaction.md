## 范围

描述用户何时介入、介入为了什么。纠偏关键词先作为候选信号，确认标签需结合上下文与对象；新增需求和正常澄清单独标注。追问率、执行／讨论比例按需从消息意图计算。接受或拒收的结果标签见 [Outcome 主观结果](<subjective-outcome.md>)。

## 特征口径

| 字段                           | 粒度／类型       | 定义与提取规则                                    |
| ---------------------------- | ----------- | ------------------------------------------ |
| `message_intents`            | 真人消息 · 标签列表 | 允许一条消息含多个意图；仅分析可确认的人类正文，词表及确认方式待定。         |
| `intervention_points`        | 真人消息 · 事件关系 | 关联任务、轮次、前后执行步骤及事件 ID；顺序优先使用记录顺序。           |
| `confirmed_correction_count` | 任务／会话 · 消息数 | 统计已确认含纠偏意图的真人消息，同一消息多个纠偏标签只计一次。            |
| `confirmed_correction_rate`  | 任务／会话 · 比例  | 确认纠偏消息数 ÷ 同范围内真人来源和意图均可判定的消息数；分母为 0 时返回空值。 |
| `repeated_requirement_count` | 任务／会话 · 消息数 | 统计首次要求之后的重复强调；对象或上下文不能确认时只保留候选。            |
| `friction_types`             | 介入事件 · 类别列表 | 结合反馈及执行上下文标注，可多标签；保留证据与未知，不直接推断情绪或人格。      |

## 分析函数

| 建议函数                                              | 输入 → 输出                  | 主要处理                     |
| ------------------------------------------------- | ------------------------ | ------------------------ |
| `classify_message_intents(messages, context)`     | 真人消息与上下文 → 意图、候选／确认状态及证据 | 区分纠偏、澄清和新需求，未知意图不强制归类。   |
| `locate_interventions(events, tasks)`             | 有序事件与任务边界 → 介入位置及摩擦候选    | 关联具体执行对象，避免混入系统注入或子代理消息。 |
| `summarize_interactions(labeled_messages, scope)` | 标注消息与筛选范围 → 纠偏、重复强调和摩擦分布 | 去重并按统一分母计算，返回有效与未知样本量。   |

## 验收样例

- “不对，我要的是 A”：关联被纠正对象；确认后计一条纠偏消息。
- “再加一个导出按钮”：若是新增需求，不能仅因要求调整就自动算纠偏。
- 没有可判定的真人消息：纠偏率返回空值，同时返回有效数为 0 和未知数。
