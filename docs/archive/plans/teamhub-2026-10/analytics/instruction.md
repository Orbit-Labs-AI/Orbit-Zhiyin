## 范围

Instruction 记录用户**这一次**对工作方式的要求。只分析能确认来自真人的主会话消息，先去掉系统包装、引用和代码示例。agent 自己说“我要运行测试”，不会被记成用户要求测试。

明确说明长期适用的习惯放在 [Preference 主观偏好](<preference.md>)。本族不根据这些要求给用户打性格分，也不把工具审批次数当成用户授权。约束密度和 prompt 具体程度的综合评分继续暂缓。

## 特征口径

| 字段 | 记录什么 | 例子与边界 |
| --- | --- | --- |
| `requested_autonomy` | 先询问、有限范围自主、明确自主授权，以及原话。 | “先询问我”记为先询问；没识别出授权时保留未知。 |
| `execution_order` | 用户明确要求的工作顺序。 | “先给方案”记为先规划；不根据 agent 后来做了什么倒推要求。 |
| `verification_requirements` | 用户要求执行的测试或核验。 | “请运行 pytest 并报告结果”能识别；这不表示测试已经通过。 |
| `allowed_scope / prohibited_actions` | 允许或禁止做什么，涉及什么文件，有什么条件。 | “只修改 src/a.py”“不要推送”；条件不明时先保留，不能当作无条件许可。 |
| `acceptance_criteria` | 用户明确提出的完成标准及证据 ID。 | “验收标准：全部测试通过”；以后可与 [Outcome 客观结果](<objective-outcome.md>)关联，本轮尚未自动匹配。 |
| `format_requirements / tool_requirements` | 明确的输出格式和工具要求。 | “请用 JSON 输出”“使用 pytest”；仅提到工具名不一定是在要求使用。 |

每个字段返回“带原文的条目列表”或未知值 `null`。未知可能是信息不足，也可能是当前规则没识别出来，不能写成“用户没有这个要求”。

## 分析函数

| 函数 | 回答什么问题 | 怎么处理 |
| --- | --- | --- |
| `instruction_text / structure` | 用户正文里有多少字符、文件引用和格式词？ | 清理包装、引用和示例，再计算原有结构指标；旧调用方式继续可用。 |
| `extract_instruction_constraints` | 这条消息提出了哪些明确要求？ | 按中英文规则识别上述八类字段，保留原话、消息位置、文件和条件。 |
| `resolve_instruction_scope` | 在指定任务、指定时刻，哪些要求可用，哪些还有疑问？ | 只看当时已出现的要求；保留条件和冲突，只有明确的替换记录才覆盖旧项。 |
| `summarize_control_patterns` | 所选消息中，有多少明确提出了各类要求？ | 按消息计数，同时报告命中数、未知数和比例。 |

举例：选中 10 条真人消息，其中 3 条能识别出核验要求，核验要求的命中比例就是 30%。剩下 7 条记为未识别，不能说它们一定没有要求。同一条消息可以同时要求测试和禁止推送，所以不同类别的比例不能简单相加。

## 验收样例

| 用户输入或场景 | 应怎样理解 |
| --- | --- |
| “先给方案，等我确认后再改文件” | 现在可以给方案；改文件要等确认。后半句的条件不应限制前半句。 |
| “只修改 src/a.py” | 记录有限授权和文件范围。 |
| “不要推送，请运行测试” | 同时记录禁止推送和核验要求。前半句的“不要”不能影响后半句。 |
| 引用或代码示例里写着“不要运行测试” | 不当作用户当前的禁止事项。 |
| “验收标准：全部测试通过” | 记录验收项，暂不判断是否已通过。 |
| 先说“不要修改 src/a.py”，后说“允许修改 src/a.py”，但没有明确替换关系 | 两条原话都保留，提示冲突，不默认最后一句自动覆盖前面。 |

### 新特征：明确格式与工具要求

- 字段、类型和粒度：`format_requirements / tool_requirements`，按消息记录，结果是带原文的条目列表。
- 用途：让“出现了格式词／工具名”的计数能够关联到具体要求。
- 输入与证据：与其他字段一样，只用可确认的真人正文；每项能回到原消息。
- 规则与缺失：识别 JSON、Markdown、表格、列表，以及 pytest、git、bash、ruff、MCP、skill 的明确使用要求。识别不到时保留未知。
- 正反例：“请用 JSON 输出”记录格式要求；“不要使用 pytest”记录禁止事项；引用中的同样文字不算当前要求。
- 负责人和进度：`MistyHuang03` 发起，Codex 实现和技术验证；更多工具名称和真实效果待补，见 [PR #16](https://github.com/Orbit-Labs-AI/Orbit-Source/pull/16)。

### 分析函数：提取、查看当前要求与汇总

- 输入输出：提取函数接收标准化消息和主会话集合；范围函数另需会话 ID、任务 ID 和可选截止时间；汇总函数接收已筛选的消息记录。
- 步骤：确认来源 → 清理正文 → 识别要求 → 保留证据 → 按任务、时间查看或按消息统计。
- 缺失处理：任务不明、时间不明或条件还未判断时单独列出；一条消息没有命中规则，仍保留为未知样本。
- 替换规则：只有上游明确标记“这条替代哪条”，并且字段、对象和条件一致时才覆盖旧项。当前还不能从任意自然语言自动判断撤销和替换。
- 示例与版本：上述验收样例已有测试，当前规则版本为 `instruction-v1`。详细参数、分母和时间边界见 [接口说明](https://github.com/Orbit-Labs-AI/Orbit-Source/blob/f9f643523ff1ea33be398a7cda3e8b11e36f02d0/src/tandem_backend/analytics/instruction/README.md)。
- 负责人和进度：`MistyHuang03` 发起，Codex 技术验证；后续工作见 [Issue #4](https://github.com/Orbit-Labs-AI/Orbit-Source/issues/4)。
