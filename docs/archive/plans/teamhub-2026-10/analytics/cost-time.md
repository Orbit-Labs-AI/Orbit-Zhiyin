## 范围

描述记录可支持的资源用量和时间。逐请求 token 与累计快照分开，缓存分项按来源口径去重；会话跨度、执行耗时和人工投入分别解释。实际／估算费用、到首次验收的时间和真实人工投入时长暂缓。执行区间由 [Respond](<respond.md>)提供。

## 特征口径

| 字段 | 粒度／类型 | 定义与提取规则 |
| --- | --- | --- |
| `token_buckets` | 模型请求 · token 数 | 明确未缓存输入、缓存读取、缓存写入、输出及来源口径；思考 token 已计入输出时不重复相加。 |
| `execution_duration_ms` | 调用／执行段 · 毫秒 | 由原生报告或可靠端点计算；日志时间差单列估算质量，缺端点记未知。 |
| `observed_session_span_ms` | 会话 · 毫秒 | 所选记录最晚有效时间减最早有效时间；只有一条有效时间时跨度为 0，并报告时间覆盖。 |
| `activity_by_day` / `activity_by_hour` | 分析范围 · 分布计数 | 按指定时区分桶，并按真人消息、主会话开始、工具调用、模型请求分别统计；缺时间不分桶。 |

## 分析函数

| 建议函数 | 输入 → 输出 | 主要处理 |
| --- | --- | --- |
| `summarize_token_usage(requests, scope)` | 请求用量与范围 → 分项、小计、完整／未知请求数 | 明确计量口径，处理包含关系；缺任一必要分项时不冒充完整总量。 |
| `summarize_durations(intervals, events)` | 执行区间与日志 → 耗时分布、区间并集与会话跨度 | 并行时间用区间并集去重，调用耗时总和单独保留；区分可靠与估算。 |
| `analyze_activity_rhythm(events, display_tz)` | 带来源的事件与时区 → 日／小时分布 | 不同活动分别分桶，返回有效和缺时间数，不把工具活动当作人工作时间。 |

## 验收样例

- 累计快照依次为 100、150 token：不能直接相加为 250；需确认计量周期和覆盖范围。
- 可靠区间分别为 0–10 秒和 5–15 秒：调用耗时总和为 20 秒，运行覆盖时间为 15 秒。
- 一条记录没有时间：不加入日／小时分布，缺时间数量增加；未知用量不能填 0。
