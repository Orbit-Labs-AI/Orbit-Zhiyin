# 画像与协作人格

Orbit 有三种不同输出：报告中的证据画像、analytics 的描述性 profile，以及 App 中的 16 型协作人格。接口名称相近，但用途与算法不同，消费者不能等待所有 profile 都返回类型码。

| 输出 | 实现 | 内容 |
| --- | --- | --- |
| 报告画像与瓶颈 | `profiling/` | 场景、明确要求、修改过程和证据案卷 |
| 描述性 profile | `analytics/presentation/profile.py` | 请求、任务分布、偏好与趋势；`produces_type_code=false` |
| App 协作人格 | `uiview/persona.py` | 四轴行为描述、类型、样本与区间 |

## 从证据形成画像

例如用户要求“面向初学者解释”，随后要求“换一个直观例子”。画像可以记录讲解要求与后续修改；瓶颈可以展示两者之间的交付。仅这些记录不足以证明原回答错误、计算浪费时间或判断某个 Skill 已有效。

消息、任务和会话各自计数。同一任务中的多条要求不能制造多个独立会话；范围和引用必须保持一致。资源目录只在匹配推荐时参与，不能反向改变用户画像。

## 四轴与类型

| 轴 | 观察单位与问题 |
| --- | --- |
| D 委托 / S 掌舵 | 真人触发轮次中的执行步数与控制方式 |
| I 即兴 / P 规划 | 会话开场的结构与计划信号 |
| M 多线 / F 专注 | 活跃日的 Agent 使用和会话重叠 |
| V 求证 / T 信任 | 当前实现选用的验证要求及行为证据 |

具体信号由 [uiview/facts.py](../../../packages/backend/src/orbit_backend/uiview/facts.py)提供，阈值集中在 [persona.py](../../../packages/backend/src/orbit_backend/uiview/persona.py) 的 `CONFIG`。当前中点为 50，判定带 45–55，低于 30 个会话给样本提示；这些是产品和展示默认值，没有人群校准依据。

类型可以在少量会话时产生，但区间、`decided` 和缺数据状态仍需保留。轮次相关时采用会话聚类的有效样本口径，不能把同一会话的重复轮次当独立样本来缩窄区间。具体数字不等于心理学上的置信度。

## 表盘与视觉

表盘将单会话按同套四轴放到类型空间，每个 Agent 一条独立曲线，共用尺度；徽章表达其会话方位的平均方向。曲线、花形和颜色是呈现方式，不是额外的分析模型。类型文案与顺序由前后端共同维护，素材见[人格设计](../../design/persona/README.md)。

## 已知限制

工具粒度、会话续接、验证来源和同日多 Agent 活动都会影响代理指标。行为归类不能用于判断个人身份、能力或心理状态。构造回归验证一致性，真实稳定性和解释质量需要独立样本与读者评价。

CLI 可用 `orbit demo --view profile`、`--view bottlenecks`、`--view process` 检查报告画像；App 类型应读取 uiview 的对应结果。参见[展示指标](presentation-metrics.md)。
