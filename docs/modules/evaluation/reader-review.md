# 怎样验“说人话”

先判断事实有没有丢，再判断读者是否读得明白。自动检查负责找明显遗漏和夸大；读者负责主次、背景适配、中文语感，以及能否复述重点。两者的结果分开保存。

生成默认材料：

```sh
.venv/bin/tandem reader-pack
```

命令会给出一个评审目录。默认六个案例均为虚构，覆盖画像、瓶颈、推荐、开发报告、数学讲解和进度说明。自己的案例通过 `--cases 路径` 提供，必须声明 `evaluation_only`，并为两种表达列出同一组必要事实。

打开 `review-X.md`，读完后在 `ratings-X.json` 填写复述与评分。A、B 隐藏表达的版本名；Y 表把顺序互换，适合交给另一位读者。不要让同一位读者的两次阅读充当两个独立样本。先阅读正文，再展开事实核对；`manifest.json` 保存版本映射，评审前先不看它。

四项评分分别看主次、读者背景、中文自然程度、事实与条件保留，范围为 0–4。无法判断时保留 `null`。只想留下意见也可以先填复述和评语；材料可以反复生成，已填写的表不会被覆盖。

汇总一份评审表：

```sh
.venv/bin/tandem reader-results --pack 评审目录 --ratings 评审目录/ratings-X.json
```

空白表保持待评价；部分填写只汇总已有信息，不补零分。正文或版本映射变动后，原评分会被拒绝混用。明确验收需要读者完成各案例的复述与评分，再填写 `acceptance.decision` 为 `accept` 或 `needs_revision`。这个结论只适用于该读者看过的案例，不能推广为所有场景都已达标。

评审命令不打开历史数据库，也不会把标准或评价写进画像。真实数据的材料应放在 `.local/`，和历史样本一样保持本地。
