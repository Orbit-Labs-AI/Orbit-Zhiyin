# 导入性能与增量边界

性能优化必须保持同一来源树的身份、事实、覆盖与发布语义不变。并行处理不意味着多个写者可同时修改 canonical 库。

## 当前策略

发现与捕获按来源组织，mapper 的准备和映射分阶段处理；可并行的文件工作产出由受控写者提交。未变化输入快速跳过，受影响会话闭包决定可局部重建的范围；需要整源一致性的情形仍按整源处理。

首次导入可以渐进发布可用结果，但每次发布都必须是自洽的投影。暂停采集与恢复补扫保留来源边界，不把中断误报为完整完成。后台同步应考虑上一轮耗时，避免同一来源连续重复重建。

## 计时口径

分别记录发现、捕获、prepare、map、derive、校验、发布与维护。文件数、原生记录数、事件数和会话数分别报告。批次进度不冒充整体百分比，耗时不能直接换算到另一台机器。

导入后的 checkpoint、压缩等维护不应混入 mapper 吞吐；`ImportService` 支持后台、等待或关闭维护。新导入可以打断后台维护并优先执行，读者继续只读已发布数据。

## 比较一个优化

使用相同源树、同路径、同 seed 与同范围，在独立 home 中比较旧路径与新路径。先验证逻辑摘要和不变量，再解释吞吐、查询延迟、WAL、磁盘与峰值内存。文件复制、重复记录和父子闭包必须有对应回归。

命令与输出字段见[数据基准](../../../benchmarks/data/README.md)。性能不是每次文档或普通功能 PR 的必跑项；历史实测与优化过程见[归档记录](../../archive/implementation/import-performance.md)，不能将其中单机数字作为当前 SLA。
