# 来源索引与轨迹读取

Orbit 的原生扫描保留来源引用、文件版本、记录定位和哈希，并生成可独立分析的 L2/L3。它不默认保存第二份完整 session 文件。桥接或归档输入则保留其相应原始字节。

## 三种读取

| 读取 | 用途 | 返回边界 |
| --- | --- | --- |
| 标准事件分页 | UI 轨迹与证据 | 已标准化、脱敏的事实；按 seq 继续 |
| 原生 trajectory | 核对原生记录结构 | 根据记录索引读取对应版本，保留去向与定位 |
| 原文下钻 | 明确选择的证据 | 原始内容可能未脱敏；来源变化或缺失时返回不可用 |

入口在 `orbit_data.query`、`Store.read_raw` 与后端 data 路由。`event_page`、`trajectory_page`、`record_source` 分别面向上表场景。HTTP 标准事件入口使用 `/v1/sessions/{session_uid}/events`，原文入口为 `/v1/records/{record_uid}/source`；是否包含内容由显式参数控制。

## 顺序与完整性

事件顺序取原生 seq，不按采集时间重排。同一原始记录可拆成多个标准事件，贡献关系保留在 `record_event`。分页限制行数，不应偷偷裁剪单条正文；显示层的截断需单独标注。

索引会校验来源版本或哈希。原文件被删除、替换或改写时，旧索引不能冒充当前原文。UI 应显示不可用原因，并允许回到仍可用的标准事实；不能拼出假的原文。

## 消费注意

分析默认读取所需标准字段，不为每次聚合加载全部扩展或原文。原文读取也必须遵守用户选定的来源、排除项和历史截止。报告导出可能带敏感内容，分享前仍需检查。

兼容归档、迁移与数据层次见[数据契约](../../contracts/data.md)。源记录不可用的排障见[用户指南](../../guides/troubleshooting.md)。
