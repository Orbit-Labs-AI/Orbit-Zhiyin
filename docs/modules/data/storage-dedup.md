# 存储、去重与维护

会话事实由 `orbit_data` 持有，迁移文件定义实际结构；当前逻辑契约仍为 v1，存储迁移已到 014。不要继续把旧的“存储 v8”当作当前库版本。

## 去重的证据

消息镜像、重复原生响应、已证明的文件副本和 fork 复制段分别处理。相同文本不能证明相同身份；不同任务重复同一句要求仍是不同记录。去重后的事件保留所有原始贡献，不能丢掉 L1 去向。

大段原生扩展使用内容寻址存储，正文与结构化字段仍能按契约读取。调用者不应依赖压缩实现或把 payload 引用当成普通文本。旧库从保留输入重建后才能获得新增派生字段，迁移不会补造未观测值。

## 查询和索引

规范事件、会话、工具/模型调用及文件操作有对应身份和查询索引。消息搜索使用 FTS 或受限回退，工具结果不无条件进入全文检索。外键逐连接启用；写入使用显式事务，读端使用一致的 query-only 快照。

WAL 允许写入与已发布数据读取并行。checkpoint、VACUUM 和统计维护只改变存储布局，不改变逻辑事实。维护前后用逻辑摘要核对，不能按数据库字节哈希判断语义等价。

## 维护入口

`Store.maintain` 负责导入后的维护，`ImportService(maintenance=...)` 选择 `background`、`wait` 或 `off`。后台维护使用独立连接，新导入优先；CLI/Benchmark 可等待以测量维护后的实际体积。

空间报告区分事实表、索引、空闲页、WAL 与 raw。删除操作按明确清单和确认词执行，不等于删除 Catalog、所有 App 状态或 Agent 源记录。见[本地数据服务](data-services.md)。

迁移定义见 [migrations](../../../packages/data/src/orbit_data/migrations/)，验证见[数据基准与完整性](../../../benchmarks/data/README.md)。
