# 安装清单的验证方法

安装清单验证的是“在已授权目录、已支持布局和扫描时刻看到什么”。它不验证整台机器的完整安装列表，也不执行插件来推断运行态。

## 必测边界

| 场景 | 应保留的结果 |
| --- | --- |
| 从未扫描 | unavailable，与已知空清单不同 |
| 支持布局为空 | available、零观察 |
| 损坏配置、权限不足或触限 | partial 与原因，其他有效观察仍可用 |
| 不支持类别 | unavailable，不解释为未安装 |
| 配置、登记、缓存同名 | 保留各自证据，不盲目合并 |
| 来源删除或禁用 | 新快照反映变化，旧快照仍可按时间查询 |
| 历史截止 | 不读取截止点之后的扫描结果 |
| 越界链接或敏感文件 | 拒绝读取，错误不包含凭据正文 |

每个 Agent 用自己布局的构造夹具定义预期，不能用扫描器输出反过来生成期望值。测试包含规则、Skill、MCP、Hook、插件和定时任务中实际支持的类别，覆盖配置目录与会话目录不同、授权额外根、profile 和插件声明路径。

## 执行与报告

运行数据包 inventory 对应测试；跨包消费变化再加相应分析/推荐回归。人工授权的本机扫描记录来源版本、目录范围、触限与未支持类别，不提交配置正文或私密路径。

对比扫描前后应解释新增、移除和状态变化。观察条数不是去重后的安装数量，启用字段未知不补 true。完整语义见[本机安装清单](local-inventory.md)，既往缺口与修复见[库存审计](../../audits/inventory-audit.md)。
